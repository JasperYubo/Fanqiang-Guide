# 基础资料库维护与完整重建

维护工具版本：v1.0 · 2026-09-12。资料快照版本：v0.1-2026-09-11。

本目录保存基础资料库的结构化原料、维护者文章和重建程序。使用 Python 3.13 标准库即可，不需要安装依赖、配置 API Key 或连接网络。

## 一条命令重建

在仓库根目录运行：

```sh
python tools/rebuild_library.py
```

它先在临时目录生成并校验全部结果，通过后才更新目标文件。运行脚本不依赖当前工作目录；默认输入、输出和观察状态均相对于脚本所在仓库解析。

建议修改原料后先生成到独立目录，查看差异再更新仓库：

```sh
python tools/rebuild_library.py --output-dir ../fanqiang-guide-rebuild-preview
python -m unittest discover -s tests -p test_rebuild_library.py -v
```

`--output-dir` 只改变生成结果的目标位置。默认仍读取本仓库的 `tools/source/` 与 `data/upstream.json`，不会抓取新版本或免费节点。要固定其他已有观察快照，可显式传入 `--state path/to/upstream.json`；该文件始终只读，缺失或格式错误会报错。隔离预览只包含本工具负责的文件，不是完整站点副本。

`--source-dir` 用于测试或显式指定另一套完整原料。构建器只读取下列固定文件，解析后的路径必须位于选定原料目录内；JSON 中记录的路径不会被当作本机文件打开。

## 必需原料

| 原料 | 用途 |
| --- | --- |
| `source/baseline.json` | 初始参考目录记录 |
| `source/baseline-reviewed.json` | 对初始目录的第一方核验补充 |
| `source/concepts.json` | 核心、协议、传输与基础概念 |
| `source/github-extra.json` | 补充工具与项目 |
| `source/routers.json` | 路由器固件、插件和相关生态 |
| `source/source-lists.json` | 资料目录及发现过程记录 |
| `source/relationship-extra.json` | 关系引用所需的补充实体 |
| `source/merlin-model-matrix.json` | 型号、固件支持声明及其来源 |

这 8 份 JSON 都是必需的记录数组，不能因缺失而跳过。额外放入其他 JSON 不会自动加入构建；新增条目应进入适合的现有原料，并保持 ID、类型、核验范围与来源明确。日期、价格、版本和搜索结果等来源声明不会因重建而升级为实测结论。

`source_evidence.local_snapshot` 等字段可能保留 `sources\concepts\…html` 形式的历史相对标识，用于解释旧采集记录；它们不是可下载文件，也不是构建依赖。本目录没有附带第三方网页全文、原始节点配置或账号凭据。

三篇维护者原稿位于 `source/knowledge/`：

- `merlin-guide-v0.1-2026-09-11.md`
- `merlin-model-matrix-v0.1-2026-09-11.md`
- `taxonomy-v0.1-2026-09-11.md`

它们以当前读者版本作为原稿，按原字节发布到 `knowledge/`，不从旧介绍或实体字段重新拼装。更新文章请编辑原稿，再运行重建；直接改 `knowledge/` 的副本会在下一次重建时被原稿覆盖。构建器只发布这 3 篇固定文章，不扫描或复制原料目录中的其他 Markdown。

## 生成范围

一次完整重建包括：

- `export/` 的主库 JSON / JSONL / SQLite、每实体一张卡片、分类索引、关系、来源、已核验及全部 RAG、待核验队列、型号矩阵与兼容 RAG。
- `config/upstream-repositories.json`：从生成后实体的 `repository` 字段重新计算映射及排除项。
- `CATALOG.md`、`UPDATES.md`：结合上述资料与只读的上游观察快照生成。
- `knowledge/` 中上述 3 篇维护者文章。

新增条目会进入相应的卡片、索引、检索集、来源、关系和仓库映射；删除条目后，其对应的同版本旧卡片会被清除。已核验 RAG、待核验队列、关系和型号记录有各自范围，不要求它们与主库拥有相同记录数。

基础索引的使用说明链接在发布时指向仓库 `README.md`。bannedbook 资料卡使用专用来源展示规则，只保留“官方仓库 · bannedbook/fanqiang”和“已阅读的 README”；该目录的搜索快照仍保留在结构化溯源数据中，不重新混入读者卡片的来源区。

此工具不会改动首页 README、`data/` 中的观察状态或 `free-proxies/` 的日期页面，也不会补抓历史节点。每日节点整理仍使用原有独立采集与页面生成流程。不要把本工具加入每日发布步骤；它供维护者修改基础资料后主动运行，离线测试只在临时目录验证重建行为。

## 无变化时保持稳定

现有基础导出文本固定使用 UTF-8 / CRLF，仓库映射与目录使用 UTF-8 / LF；文章原稿按字节复制。固定输入和观察状态的重建应保持文本一致，已有内容相同时不重写文件。

SQLite 先在临时目录完整新建并检查完整性，再比较应用表结构、排序后的逻辑记录和检索结果。逻辑相同就保留现有数据库文件及修改时间；逻辑不同才原子替换成校验过的新数据库。不会在现有数据库上先删表重建，也不把无意义的 SQLite 存储布局差异提交进仓库。

所有必需输入先完整读取，随后在临时目录构建和检查实体、卡片、来源、关系、型号及 RAG 的引用一致性。缺文件、非法 JSON 或无效引用会在正式输出替换前失败；发布阶段只处理明确列出的生成文件。

## 验证与维护边界

`tests/test_rebuild_library.py` 覆盖现有快照完整重建、数据库不变时不替换、合成实体新增／改为待审／删除的全链回归、必需输入逐个缺失、S02 来源规则保持、文章原稿保留、输入路径越界和状态／日报不被修改。

验证过程中使用合成实体，不联网、不访问节点。快照版本及默认记录日期由构建器中的 `STAMP` / `DATE` 固定，单纯运行重建不会宣称完成新一轮资料核验。
